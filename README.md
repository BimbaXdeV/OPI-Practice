## 1. Вступ (Introduction)

«Сад» — мобільний застосунок для підтримки особистих стосунків з рідними та близькими людьми.
Замовник: команда розробників застосунку «Сад».
Проблема: люди забувають підтримувати зв'язок з близькими через зайнятість, але відчувають провину за це. Застосунок вирішує це без тиску та шеймінгу.
Цільова аудиторія: користувачі від 5 років, які хочуть підтримувати соціальні зв'язки з родиною та друзями.

## 2. Загальний опис (Overall Description)

### Актори

| Актор | Роль |
|-------|------|
| Незареєстрований користувач | Перегляд інформації про застосунок, реєстрація |
| Зареєстрований користувач | Основний актор: додає контакти, отримує нагадування, взаємодіє з садом |
| Адміністратор | Управління обліковими записами та модерація |

### Функціональні блоки

- Система реєстрації / авторизації (email + пароль)
- Менеджер контактів з індивідуальними налаштуваннями частоти спілкування
- Система нагадувань (push-повідомлення, не більше одного разу на добу)
- Візуалізація «Саду» (стан рослин відображає активність спілкування)

### Зовнішні залежності

- Firebase / локальна база даних на пристрої (дані зберігаються локально)
- FCM — Firebase Cloud Messaging (push-повідомлення)
- SMTP-сервер (підтвердження email при реєстрації)

## 3. Функціональні вимоги (Functional Requirements)

| ID | Пріоритет | Вимога |
|----|-----------|--------|
| FR-01 | Must | Система дозволяє реєстрацію через email та пароль |
| FR-02 | Must | Користувач може додавати контакти (не обов'язково прив'язані до номера телефону) |
| FR-03 | Must | Для кожного контакту можна налаштувати індивідуальну частоту нагадувань (частіше / рідше) |
| FR-04 | Must | Система надсилає не більше одного push-нагадування на добу на контакт |
| FR-05 | Must | Застосунок відображає «Сад», де кожна рослина відповідає одному контакту |
| FR-06 | Must | Рослина росте та яскравіє при регулярному спілкуванні з контактом |
| FR-07 | Must | Рослина починає «вмирати», якщо спілкування припинилося — надходить нагадування |
| FR-08 | Should | Користувач може надіслати картинку або повідомлення контакту прямо з застосунку |
| FR-09 | Should | Користувач може видалити або редагувати контакт |
| FR-10 | Could | Перегляд історії взаємодій з конкретним контактом |

## 4. Нефункціональні вимоги (Non-Functional Requirements)

### Продуктивність

| ID | Вимога |
|----|--------|
| NFR-P-01 | Час відповіді застосунку для 95% дій < 1.5 с при 500 000 зареєстрованих користувачів |
| NFR-P-02 | Push-нагадування доставляється протягом 60 секунд від запланованого часу |

### Безпека

| ID | Вимога |
|----|--------|
| NFR-S-01 | Паролі зберігаються у вигляді хешів (bcrypt, cost factor ≥ 12) |
| NFR-S-02 | Передача даних здійснюється лише через HTTPS (TLS 1.2+) |

### Зручність використання

| ID | Вимога |
|----|--------|
| NFR-U-01 | Інтерфейс інтуїтивно зрозумілий для користувачів від 5 років |
| NFR-U-02 | Усі ключові дії виконуються не більше ніж у 3 натискання |

### Надійність

| ID | Вимога |
|----|--------|
| NFR-R-01 | Uptime серверної частини ≥ 99% на місяць |
| NFR-R-02 | Дані користувача зберігаються локально на пристрої та не втрачаються при перезапуску застосунку |

### Масштабованість

| ID | Вимога |
|----|--------|
| NFR-SC-01 | Архітектура підтримує до 500 000 одночасно зареєстрованих користувачів |
| NFR-SC-02 | Система нагадувань масштабується без змін коду при збільшенні бази користувачів |

## 5. Обмеження (Constraints)

| ID | Обмеження |
|----|-----------|
| C-01 | Застосунок розробляється виключно для мобільної платформи Android |
| C-02 | Персональні дані користувача зберігаються локально на пристрої, не на сервері |
| C-03 | Бюджет: від $5 000 до $7 000 |
| C-04 | Дедлайн MVP: 2–3 місяці від дати початку розробки |
| C-05 | Реєстрація є обов'язковою; уся особиста інформація є конфіденційною |

## 6. Глосарій (Glossary)

| Термін | Визначення |
|--------|-----------|
| **Сад (Garden)** | Візуальна метафора у застосунку: колекція рослин, кожна з яких символізує стосунки з одним контактом |
| **Рослина (Plant)** | Елемент саду, що відображає активність спілкування з конкретним контактом |
| **Неагресивне нагадування** | Push-повідомлення, яке з'являється не частіше одного разу на добу і не вимагає негайної реакції |
| **Контакт** | Особа, яку користувач додав до застосунку для підтримки зв'язку |
| **MVP** | Minimum Viable Product — мінімальна робоча версія продукту з базовим набором функцій |
| **FCM** | Firebase Cloud Messaging — сервіс для відправки push-повідомлень на Android-пристрої |
| **CRUD** | Create, Read, Update, Delete — базові операції над даними |

## 7. Матриця відстежуваності (Traceability Matrix)

| Вимога | Джерело (питання інтерв'ю) | Тест-критерій |
|--------|---------------------------|---------------|
| FR-01 | «Чи обов'язкова реєстрація?» | Тест: успішна реєстрація нового email + вхід в акаунт |
| FR-02 | «Які функції повинна мати програма?» | Тест: додавання контакту без номера телефону |
| FR-03 | «Індивідуальний підхід до контактів» | Тест: різна частота нагадувань для двох різних контактів |
| FR-04 | «Що таке неагресивне нагадування?» | Тест: не більше 1 push-повідомлення за 24 год на контакт |
| FR-05, FR-06, FR-07 | «Опис продукту, візуалізація саду» | Тест: рослина збільшується після взаємодії; рослина починає вмирати після 3 днів без контакту |
| FR-08 | «Опис базових функцій застосунку» | Тест: успішна відправка картинки через застосунок |
| NFR-SC-01 | «Яке навантаження очікується на сервери?» | Навантажувальний тест на 500 000 користувачів |
