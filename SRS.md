## 1. Вступ (Introduction)
«Garden» — мобільний застосунок для підтримки особистих стосунків з рідними та близькими людьми.
Замовник: Команда 3-3 (згідно з умовами проєктного інтерв'ю).
Проблема: люди часто забувають підтримувати зв'язок з близькими через зайнятість, але відчувають провину за це. Застосунок вирішує цю проблему без тиску, шеймінгу та нав'язування терміновості.
Цільова аудиторія: користувачі віком від 5 років, які хочуть підтримувати теплі соціальні зв'язки з родиною та друзями.

---

## 2. Загальний опис (Overall Description)

### Актори
* **Незареєстрований користувач** — перегляд інформації про застосунок, створення облікового запису.
* **Зареєстрований користувач** — основний актор: додає контакти, отримує нагадування, взаємодіє з віртуальним садом, відправляє медіафайли.
* **Адміністратор** — управління обліковими записами та загальна модерація.

### Функціональні блоки
* Система реєстрації / авторизації (email + пароль).
* Менеджер контактів з індивідуальними налаштуваннями частоти спілкування.
* Система нагадувань (push-повідомлення, не більше одного разу на добу на контакт).
* Візуалізація «Саду» (стан кожної рослини відображає активність спілкування з певним контактом).

### Зовнішні залежності
* **FCM (Firebase Cloud Messaging)** — для push-повідомлень на пристрій.
* **SMTP-сервер** — для підтвердження email під час реєстрації.
* **Локальна база даних (SQLite / Room)** — основні дані користувача зберігаються локально на пристрої; сервер використовується лише для базової авторизації та роботи push-сервісу.

## 3. Функціональні вимоги (Functional Requirements)
* **FR-01 [Must]:** Система дозволяє реєстрацію через електронну пошту та конфіденційний пароль.
* **FR-02 [Must]:** Користувач може додавати контакти (без обов'язкової прив'язки до номера телефону).
* **FR-03 [Must]:** Для кожного контакту користувач може налаштувати індивідуальну частоту нагадувань (частіше / рідше).
* **FR-04 [Must]:** Система надсилає не більше одного неагресивного push-нагадування на добу на кожен контакт.
* **FR-05 [Must]:** Застосунок відображає віртуальний «Сад», де кожна окрема рослина відповідає одному контакту.
* **FR-06 [Must]:** Рослина збільшується та стає яскравішою при регулярному спілкуванні з відповідним контактом.
* **FR-07 [Must]:** Якщо спілкування припинилося, рослина починає «вмирати», а система надсилає повідомлення-нагадування.
* **FR-08 [Should]:** Користувач може надіслати картинку або базове повідомлення контакту безпосередньо із застосунку.
* **FR-09 [Should]:** Користувач має змогу видалити або відредагувати існуючий контакт.
* **FR-10 [Could]:** Система дозволяє перегляд історії взаємодій (надісланих повідомлень/картинок) з конкретним контактом.

## 4. Нефункціональні вимоги (Non-Functional Requirements)

### Продуктивність (Performance)
* **NFR-P-01:** Час відповіді серверних запитів (авторизація) для 95% операцій має складати < 1.5 с.
* **NFR-P-02:** Push-нагадування доставляється протягом 60 секунд від запланованого тригера.

### Безпека (Security)
* **NFR-S-01:** Паролі зберігаються виключно у вигляді хешів (bcrypt, cost factor ≥ 12).
* **NFR-S-02:** Передача даних між клієнтом та сервером здійснюється лише через HTTPS (TLS 1.2+).

### Зручність використання (Usability)
* **NFR-U-01:** Інтерфейс має бути інтуїтивно зрозумілим для користувачів віком від 5 років без попереднього навчання.
* **NFR-U-02:** Усі ключові дії (додавання контакту, відправка картинки) виконуються не більше ніж у 3 натискання.

### Надійність (Reliability)
* **NFR-R-01:** Uptime серверної частини (авторизація та push-сервіс) має складати ≥ 99% на місяць.
* **NFR-R-02:** Дані про контакти та стан саду зберігаються локально на пристрої та не втрачаються при відсутності інтернету або перезапуску застосунку.

### Масштабованість (Scalability)
* **NFR-SC-01:** Серверна інфраструктура (авторизація та push) повинна підтримувати навантаження до 500 000 користувачів одночасно.
* **NFR-SC-02:** Система планування нагадувань масштабується без змін коду при експоненційному збільшенні бази користувачів.

## 5. Обмеження (Constraints)
* **C-01:** Застосунок розробляється виключно для мобільної платформи Android.
* **C-02:** Персональні дані та контакти користувача зберігаються локально на пристрої (конфіденційність by design), а не на серверах.
* **C-03:** Бюджет на реалізацію проєкту складає від $5 000 до $7 000.
* **C-04:** Дедлайн готовності MVP: 8–12 тижнів (2–3 місяці) від дати початку розробки.
* **C-05:** Реєстрація є обов'язковою умовою для використання продукту.
* **C-06:** Графік розробки передбачає, що останні 1–2 тижні перед релізом виділяються виключно на процеси тестування.

## 6. Глосарій (Glossary)
* **Сад (Garden)** — ключова візуальна метафора у застосунку: колекція рослин, кожна з яких символізує стан стосунків з одним контактом.
* **Рослина (Plant)** — динамічний елемент саду, що відображає рівень активності спілкування з конкретною людиною.
* **Неагресивне нагадування** — Push-повідомлення, яке з'являється не частіше одного разу на добу на контакт, має дружній тон і не викликає почуття провини за пропущене спілкування.
* **Контакт** — особа, яку користувач додав до застосунку для підтримки регулярного зв'язку.
* **MVP (Minimum Viable Product)** — мінімально життєздатна версія продукту з базовим набором заявлених функцій (реєстрація, сад, контакти).
* **FCM (Firebase Cloud Messaging)** — хмарний сервіс для відправки повідомлень на пристрої Android.
* **CRUD** — Create, Read, Update, Delete — базові операції над даними.
